# kairon

## 概要
cron は時間を指定するスケジューラーだが、kairon は条件を指定するスケジューラーである。cron の由来は chronos だが、kairon の由来は kairos にちなむ。

たとえば「現在時刻が 9～11 時の間、かつ今日のログ書き込みが 2 件以下」といった指定ができる。LLM はこの条件を読み、現在日時を取得し、ログの今日の部分も取得した上で、当てはまるかどうかを考える。LLM ゆえに完全な精度は保障できないが、自然言語で柔軟に指定できる。そもそも LLM は 2026-05 現在、この程度の条件ならほぼ問題なく対応できるはずだ。

## 概念と参考実装
kairon が示すのは概念であり、上記概要で説明は終えている。本当は cron のようなデファクト・スタンダードを狙いたいが、狙って狙えるものではない。おそらく今後、条件指定ベースのスケジューラーを組み込んだプラットフォームやフレームワークが登場し、それが界隈に広まって標準となるだろう。そのとき、それを kairon を呼ぶことになるのだと思う。

さて、以降では参考実装を提供する。

## kairon-sta
筆者 sta の参考実装ということで、kairon-sta と名付けておく。

以下のファイルが存在する:

- kairon.py
    - kairon-sta 本体
    - 起動すると agents.md を読みつつ、現在日時など現在の文脈を取得しながら「起動対象となるエージェント」を判断する。その後、起動対象をどう処理していくかの戦略を練ってから、そのとおりに実行していく。これを judgement → strategy → execution の流れであることから **JSE フロー** と呼ぶ
    - パフォーマンスとトラブルシューティングの問題から、単一の claude -p のみを起動するべきだ。起動対象ごとにサブプロセスとして claude を起動してはならない。だからこそ JSE フローを採用している。kairon-sta から起動される単一の claude が、各エージェントの処理も自ら担うわけである。ただしサブエージェントなど Claude Code 内部の並列ロジックは使っても良い
- agents.md
    - 1-大見出し 1-Agent で書く
    - 各 Agent は 1 つの名前、1 つの条件、1 つの本文を持つ
- logs/xxxx.log
    - エージェント名 xxxx のログを書き込む
    - ログはエージェントの呼び出し頻度などコンテキストを残す主要な手段である。たとえば条件としてログの記載内容を使えるようになる
    - すべてのエージェントは、少なくとも自分が呼ばれたときはその旨をログに書き込むべきである（実際に書き込むのは本体）

kairon-sta は以下をしない:

- 本体の呼び出し方の設定
    - たとえば Windows スケジューラーに自らを登録するといった責務は負わない
    - どう呼び出すかは kairon-sta の利用者が運用することであり、kairon-sta は関知しない
    - kairon-sta は、ただ呼ばれたら agents.md を走査して当てはまるエージェントを起動するだけである
- スクリプトやコマンドの実行
    - 理由は単純で、セキュリティ上のリスクが高いからだ
    - したがって kairon-sta は、それらを実行しない程度の、簡素な行動しか行えない

本体から呼び出す claude のコマンドラインオプションは、以下を参照せよ:

```py
CLAUDE_BASE = ["claude", "-p", "--permission-mode", "dontAsk"]
ALLOWED_TOOLS = ["Read", "Write", "Edit", "Glob", "Grep", "WebSearch", "WebFetch"]
```

```py
def time_args() -> list[str]:
    now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    return ["--append-system-prompt", f"現在日時: {now}"]
```
